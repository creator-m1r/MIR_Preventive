# MIR Preventive — концепция продукта

## 1. Идея

MIR Preventive — это инфраструктура профилактического скрининга, которая стремится сделать регулярное наблюдение за организмом быстрым, объективным и непрерывным.

Ключевая идея: вместо редкого события «человек заболел → пошёл обследоваться» создать цикл:

```text
наблюдение → модель → динамика → сигнал → профилактика → повторное наблюдение
```

## 2. Диагностическая станция

Пользователь проходит короткую процедуру измерения. Станция может объединять камеры и другие сенсоры, если их применение доказало достаточную точность для конкретной задачи.

Потенциальные классы наблюдений:

- внешний вид и геометрические признаки;
- температура и тепловые характеристики;
- частота сердечных сокращений и другие доступные физиологические показатели;
- дыхательные характеристики;
- поза, симметрия и двигательные паттерны;
- рост, масса и антропометрия;
- дополнительные инструментальные измерения.

Конкретный набор сенсоров определяется задачей, качеством измерения и требованиями клинической валидации.

## 3. Персональная модель

После получения наблюдений формируется цифровое представление текущего состояния организма. Оно не является копией организма и не должно выдавать модельные значения за непосредственно измеренные.

Модель хранит:

- наблюдения;
- производные параметры;
- временные ряды;
- индивидуальные baseline;
- качество данных;
- версии вычислительных моделей;
- связи между показателями.

## 4. Профилактический цикл

```text
01. Идентификация и согласие
02. Сбор наблюдений
03. Контроль качества
04. Нормализация
05. Обновление персональной модели
06. Анализ динамики
07. Формирование риск-сигналов
08. Проверка AI Supervisor
09. Рекомендация следующего шага
10. Сохранение результата и аудита
```

## 5. Типы результата

Результат должен быть структурирован, например:

- `MEASURED` — непосредственно измерено;
- `DERIVED` — вычислено из измерений;
- `TREND` — обнаружено изменение во времени;
- `RISK_SIGNAL` — математический риск-сигнал;
- `PREVENTIVE_ADVICE` — профилактическая рекомендация;
- `RECHECK` — требуется повторная проверка;
- `MEDICAL_REVIEW` — рекомендуется медицинская оценка;
- `INSUFFICIENT_DATA` — данных недостаточно.

## 6. Пользовательский интерфейс

Интерфейс должен отвечать на три вопроса:

1. Что мы реально измерили?
2. Что изменилось по сравнению с предыдущими наблюдениями?
3. Что разумно сделать дальше?

Не следует перегружать пользователя медицинскими терминами без объяснения.

## 7. Долгосрочное преимущество

Главная ценность продукта — не единичный двухминутный скрининг, а накопление качественной временной истории. Повторные наблюдения позволяют оценивать направление изменений и отделять устойчивые тенденции от случайного шума.

## 8. Граница продукта

MIR Preventive не должен обещать невозможное. Формулировки «точно определяет все заболевания», «полностью заменяет врача» или аналогичные заявления недопустимы без конкретного доказательного и регуляторного основания.
