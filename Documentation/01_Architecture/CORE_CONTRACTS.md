# Core Contracts

Этот документ фиксирует границы доменного ядра MIR Preventive и правила обмена данными между подсистемами.

## Dependency Direction

```text
UI / Station / Integrations
          ↓
 Application / Orchestration
          ↓
       Core Domain
          ↓
 Pure domain contracts
```

Core не зависит от UI, LLM, конкретной БД, сети или конкретного сенсора.

## Required Properties

Все объекты, влияющие на аналитический результат, должны иметь стабильный идентификатор и временную метку. Производные результаты дополнительно связываются с provenance и версией алгоритма.

## Immutability

Исходное измерение после принятия в систему не изменяется. Исправление создаёт новую версию или событие с явной связью с исходным объектом.

## Unknown ≠ Zero

Отсутствующее значение представляется отсутствием данных, а не числом `0`.

## Clinical Boundary

Core не содержит утверждений о наличии заболеваний. Медицински значимые интерпретации подключаются отдельными валидируемыми модулями.

## Event Contract

События должны быть типизированными, идентифицируемыми, временно маркированными и пригодными для аудита и повторной обработки.

## Determinism

Где возможно, доменные вычисления должны быть детерминированными. Недетерминированные AI-компоненты находятся за явным интерфейсом и не должны менять смысл исходных данных.
